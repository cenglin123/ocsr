# 具名失败模式细则 — 详细参考

> 本文件从 SKILL.md §五 下沉。主文件保留产物回收清单、看门狗、硬停止与失败切换阶梯；本文件承载两类需主动裁决的细则：路径审计判断准则与越界写入覆盖的根因/对治。

## 路径审计判断准则

> §五「检查报告是否引用了不该访问的路径」中，**「不该访问的路径」的明确判断准则**：
> - **不该访问** = 提前获取答案的（如提前看到产物本身、提前看到 reviewer 的 verdict）、作弊性质的（借用未来轮次才应存在的信息、绕过任务边界）
> - **不算不该访问** = 为了更充分获取信息以解决问题的（合法的、面向任务的、非作弊性的信息收集——包括读必要前置文件、读必要规范文档、读必要先例）
>
> 该判断作为 reviewer 产物路径审计的统一准则，与 §七 越界写入覆盖防护、§七 `--dir` 风险提示配合。

## 越界写入 / 路径碰撞（具名失败模式细则）

- **越界写入 / 路径碰撞**：`opencode` **进程正常退出（exit=0）、期望产物未落盘、而写入照常发生在别处**——子代理自行选择了文件名，可能覆盖同目录内其他 agent 的产物并使其永久丢失。指纹与前两类都不同：进程已退出（非停滞）、且确实产出了内容（非报告幻觉），只是落在了错误路径。看门狗按"期望文件是否落盘"判定，会把它误报为失败，从而掩盖真实损失。
  - **根因**：`--output-pattern` 只告诉看门狗等哪个文件，**不约束子代理的写入路径**。当 prompt 的【输出】节含未解析占位符（如 `<你的 label>.md`）时，每个子代理自行发明文件名，同模型的两次派发极易撞同一个名字。
  - **对治**：① prompt 的【输出】节**必须写死唯一绝对路径**，禁止任何占位符，并把后果写明（"该目录内已有其他 agent 的报告，写错文件名会覆盖并永久销毁它们"）——只给约束不给理由时，模型会在自觉"另一个名字更合理"时自作主张；② 派发前备份 `--output-dir` 既有产物；③ 调用方驱动器应内置派发前后目录快照比对，检出覆盖时打印被覆盖文件的前后字节数并报错退出。

## 看门狗误杀

**症状**：大颗粒任务（整文件重写、多阶段编排）产物已基本落盘、仅剩收尾输出（如最终报告）时，看门狗按常规阈值（15–20 分钟）超时杀进程，判为失败——实际工作已完成大半甚至全部。
**根因**：默认阈值按判断密集单轮（1.5–7.9 分钟）的分布设定，与任务预估产出量不匹配；收尾阶段恰好落在阈值外。
**对治**：阈值按任务预估产出量上调（大规模单任务建议 60 分钟）；误杀收尾中的 worker 比多等更贵。被杀后按路径 B 续派补交剩余产物即可，无需重跑整个任务。

## 锚定污染（具名失败模式）

- **症状**：评审子代理的报告中出现对并行/前轮 reviewer 结论的引用、复述或趋同——独立评审退化为互相锚定，多视角覆盖名存实亡。
- **指纹**：执行证据（或 `reads:` 列表）含其他 reviewer 的报告路径；findings 与另一 reviewer 高度重叠；verdict 在无独立证据的情况下与他人一致。
- **根因**：①被审产物与 reviewer 产出共享可读父树，reviewer 读产物时向上一级即可发现 round 输出；②prompt 只声明必读材料、未显式禁止 siblings；③声明的可读范围（如整个 skill 目录）字面上覆盖了收敛工作目录。
- **对治**：①布局分离（staging 与收敛工作目录不共享父树，见 refs/dispatch-patterns.md §评审锚定防护）；②`--forbid-paths` 机械注入禁令 + 落盘后 `reads:` 审计；③审计 violated 按 SKILL.md §五 准则裁决——默认作废重派，能可核验证明实质独立性保留时方可降级保留并标注。
- **实证**：2026-08-04 init-agent-docs 机制诊断 ultraverge，Reviewer 2（deepseek）读取并行 Reviewer 1 报告；因 findings 零重叠且独立否定对方误读而降级保留。
