# OCSR 渐进式披露重构计划

状态：已完成；最终独立终验已批准

## 目标

将 `SKILL.md` 重构为面向 Agent 的最小默认入口：让只需一次受控派发的调用者先获得足够、明确且不可误解的操作路径；仅在实际启用并发、独立评审、脱管运行、converge 对接、`run --spec` 或层级指挥时加载对应细则。

## 非目标与不变量

- 不改变 OCSR 的定位：它仍是执行后端，不替代顶层 Agent 的任务拆解、预算裁决或最终判断。
- 不弱化安全、预算、证据或失败停止规则；`--dir`、prompt 禁令和路径审计均不得被表述为安全沙箱。
- 不新增以任务名称或关键词枚举为核心的路由表；路由只基于实际启用的能力与风险。
- 只在有可观察的重复性失误证据时新增脚本或运行时机制。

## 目标信息架构

`SKILL.md` 以约 120–160 行为目标范围，而非硬上限；若与默认安全闭环的清晰、可执行表达冲突，后者优先。它保留五块内容：

1. 使用边界：何时不要派发，以及 OCSR 的一次性 fresh-context 模型。
2. 默认派发闭环：自足 prompt、`dispatch --watch`、产物验收和调用上限。
3. 常驻硬事实：不是安全沙箱；不采信完成自述；未经授权不扩大调用预算。
4. 能力入口：以“是否需要并发 / 独立评审 / 脱管 / 治理对接 / 多步骤恢复”为条件，链接至对应的唯一目标专题。
5. 最小模型与验证入口：模型白名单、可用性检查和 driver 的事实源位置。

详细的 Windows 编码、手写脱管模板、完整失败指纹、模型角色表、run-spec schema 和层级指挥协议继续保留在 `refs/`，不在默认入口重复。

`SKILL.md` 是全局政策、边界与默认路径的唯一规范入口：每条硬约束在主文件保留可执行的短表述。每个由它条件链接的 `refs/`，在其委托的 schema 或操作细节范围内是唯一详细规格；它们不得改变或放宽主文件的不变量。迁移矩阵必须记录这种委托范围，并逐项核对主文件摘要与详细规格不冲突。

## 默认路径必留清单

下列内容必须留在 `SKILL.md` 的默认阅读路径，不能仅以链接替代：

- OCSR 的适用边界、一次性 fresh-context 模型与不适用场景。
- 自足 prompt 的六个组成部分，以及输入/输出路径不是安全隔离的事实。
- 白名单模型、首次使用时的可用性检查，以及派发前披露调用上限。
- `dispatch --watch` 的默认闭环与期望产物的唯一命名/路径要求。
- 验收顺序：存在、非空、数量、抽样内容；不采信子代理完成自述。
- 失败止损：每个 worker 最多三次总尝试；有副作用但不能证明幂等的任务不得自动重派。
- 不得把 `--dir`、prompt 禁令或路径审计表述为安全沙箱；converge 调用不得绕开预算门与证据链。

## 实施步骤

1. 前置阅读与基线：阅读 `docs/CURRENT.md`、`docs/STRUCTURE.md`、`docs/overview.md`、`docs/pitfalls.md` 和相关 `refs/`；记录现有章节、重复规则、验证器已覆盖的硬约束，并完成能力迁移矩阵。
2. 裁决事实源与导航：确认主文件作为全局规范入口、条件专题作为受委托详细规格的边界符合本计划；逐项记录委托范围与冲突优先级。检查 `docs/STRUCTURE.md` 是否仍能准确导航计划与专题，只有职责发生变化时才更新索引。
3. 设计最小入口：重写为目标信息架构，逐项保留默认路径必留清单，并让每个进阶链接按能力条件可发现。
4. 下沉细节：只移动已有、可定位的展开说明到矩阵指定的目标专题；fresh 对抗评审的布局分离、禁读、审计、作废/重派细则必须在 `refs/failure-modes.md` 内闭合。同步改写 `refs/run-spec.md` 的对齐表：提取成功后的 route 未命中 → 必填 `"*"` → `pause`；提取失败、schema、步骤类型、模板或 journal 契约失败 → fail-closed。若目标专题无法承接完整闭环，停止下沉，优先扩充已有专题而非新建文档。
5. 验收迁移：逐项试走默认单 worker 路径；逐一解析条件链接并核对其闭环、委托范围与优先级。对验证器未覆盖的迁移风险，使用矩阵逐项人工检查；为多步骤恢复分别加入两类负例：未命中具名 route 的已提取值只经 `"*"` 进入 `pause`，而 schema、步骤类型、模板或 journal 契约失败 fail-closed；同时逐项检查 `refs/run-spec.md` 的路由章节、对齐表和退出语义不再互相矛盾。只有存在重复、可观察的失误证据时才新增离线断言。
6. 机械验证：运行 `python scripts/verify_ocsr_skill.py`、`python scripts/agent_links.py check`、`python scripts/audit.py check`、`pytest tests/ -q` 与 `git diff --check`。
7. 治理评审：由于修改 `SKILL.md` 的 Agent 行为准则，取得独立新上下文 reviewer 的证据；重点审查默认路径完整性、主文件/refs 的事实源一致性、条件链接闭环、安全边界与场景枚举回流。
8. 收口：根据评审修订；更新 `docs/CURRENT.md`，必要时仅记录对维护有价值的变更到 CHANGELOG，并将完成计划移至 completed。

## 验收标准

- 普通单 worker 调用者无需读取任何 `refs/`，即可正确完成“派发—看护—验收”闭环。
- 启用任一进阶能力时，入口能明确指出唯一需要加载的专题，而不是要求通读全部文档。
- 迁移矩阵的每条能力均有主文件规范性摘要、唯一目标专题的展开职责、完整闭环和验证证据；所有原有硬约束仍可从默认入口或其明确的条件入口找到。
- `SKILL.md` 的全局不变量与每个条件专题的受委托详细规格关系明确、逐项一致，且验证脚本和测试均通过。
- 独立 reviewer 能仅凭 `SKILL.md` 与其条件链接识别默认路径、边界与升级路径。

## 风险与裁决点

- 过度压缩会让 Agent 遗漏预算、验收或安全边界；遇到此风险，保留规则的短摘要而非把规则完全隐藏。
- 过度拆分会增加跳转成本；若某条规则在普通单 worker 路径每次都必需，则留在 `SKILL.md`。
- 若审查发现展开细节间存在重复，以一个专题作为该细节的唯一承载处；`SKILL.md` 保持全局不变量与默认路径，受委托专题仅在其明确范围内定义详细规格，其他位置只保留条件链接。
